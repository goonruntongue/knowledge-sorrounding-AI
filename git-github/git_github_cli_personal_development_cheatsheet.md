# 個人開発のための Git / GitHub CLI 実用コマンド集

個人でWebサイトやアプリを作るときに、まず使えれば十分なGitとGitHub CLIの早見表です。

## まず押さえる言葉

| 言葉 | 意味 |
| --- | --- |
| Git | PC内でファイルの変更履歴を管理するバージョン管理ツール |
| GitHub | Gitのリポジトリをネット上に保管・共有できるサービス |
| リポジトリ | プロジェクト本体と、その履歴の保管場所 |
| `main` | 普段作業する本線のブランチ名 |
| `origin` | GitHub上の接続先（リモート）に付ける慣習的な名前 |
| コミット | 「この状態で保存する」という履歴の単位 |
| push | ローカルのコミットをGitHubへ送ること |
| pull | GitHub側の自分が未取得の変更をローカルへ取り込むこと |

## 最初の一度だけ：GitHub CLIへログイン

```bash
gh auth login
```

ログインできているかは、次で確認できます。

```bash
gh auth status
```

## 新しいサイトをローカルで作り、後からGitHubへ登録する

作業フォルダへ移動してから、順番に実行します。

```bash
git init
git add .
git commit -m "初回作成"
gh repo create
```

`gh repo create` の対話では、概ね次を選びます。

- **既存のローカルリポジトリをGitHubへpushする**
- リポジトリ名を入力する
- 公開範囲は通常 **Private**
- リモートを追加する：**Yes**
- リモート名：**origin**
- 既存コミットをpushする：**Yes**

これでGitHubにリポジトリが作られ、初回のデータも送信されます。

> `git init` は、そのフォルダをGitで管理し始めるための最初の宣言です。`git clone` で取得したフォルダでは、すでに済んでいるため不要です。

## GitHubにある既存プロジェクトをローカルへ持ってくる

作業フォルダを置きたい場所で、まず自分のリポジトリ一覧を見ます。

```bash
gh repo list --limit 100
```

選んだリポジトリをcloneします。

```bash
gh repo clone ユーザー名/リポジトリ名
```

例：

```bash
gh repo clone flashmelody/my-website
```

同名の作業フォルダが作られます。そのフォルダ内へ移動して作業します。

```bash
cd my-website
```

## 日常の更新：この4つが基本

作業を始める前、または終える前に状態を確認します。

```bash
git status
```

変更を履歴として保存し、GitHubへ送ります。

```bash
git add .
git commit -m "スマホ表示を調整"
git push
```

### それぞれの意味

| コマンド | 意味 |
| --- | --- |
| `git status` | いま変更中・保存待ちのファイルを確認する |
| `git add .` | 現在のフォルダ以下の変更を、次のコミット対象として選ぶ |
| `git commit -m "コメント"` | コメント付きでローカル履歴に保存する |
| `git push` | ローカルのコミットをGitHubへ送る |

## GitHub側の最新を取り込む

別PCで作業した、GitHubサイト上で編集した、または他者・AIがpushした場合は、作業前に取り込みます。

```bash
git pull
```

ローカルに未コミットの変更があるときは、先に安全に保存してから実行します。

```bash
git status
git add .
git commit -m "pull前の作業を保存"
git pull
```

`pull` の後にローカルの新しいコミットをGitHubへ送りたい場合は、さらに次を実行します。

```bash
git push
```

> GitHub側にも自分が未取得の更新がある場合、通常の `git push` は上書きを防ぐために拒否されます。その場合は `git pull` で取り込んでからpushします。同じ行を双方で変更していると、競合を解決する必要があります。

## 履歴を見る

見やすい一覧形式です。

```bash
git log --oneline
```

出力例：

```text
a1b2c3d スマホ表示を調整
e4f5g6h ヘッダーを追加
i7j8k9l 初回作成
```

左側の英数字がコミットIDです。先頭の数文字を指定して使えます。

## 昔の状態を一時的に確認する

過去のコミットを直接開いて確認します。

```bash
git switch --detach 1234abcd
```

確認が済んだら、通常の本線へ戻ります。

```bash
git switch main
```

`--detach` は「ブランチからいったん離れ、指定したコミットを直接見る」オプションです。確認用として使い、この状態でそのまま作業を続けるのは避けます。

## 昔の状態を、現在のmainへ安全に復元する

まず未保存の作業がないことを確認します。残っていれば、先にコミットしておきます。

```bash
git status
```

指定した昔のコミットの内容を、現在の作業フォルダへ復元します。

```bash
git restore --source 1234abcd -- .
```

その復元結果を、新しいコミットとして保存・送信します。

```bash
git add .
git commit -m "以前の状態に復元"
git push
```

この方法は履歴そのものを消しません。「以前の状態に復元した」という新しい記録を残したまま、ファイル内容を昔の版にできます。

### `--source` と後ろの `-- .`

```bash
git restore --source 1234abcd -- .
```

| 部分 | 意味 |
| --- | --- |
| `--source 1234abcd` | 復元元となるコミットを指定するオプション。`--source=1234abcd` と書いても同じ |
| `--` | オプション指定はここまで、という区切り |
| `.` | 現在のフォルダ以下すべて |

`--detach` は値を取らないON/OFFオプションなので、次の形です。

```bash
git switch --detach 1234abcd
```

`--detach=1234abcd` とは書けません。

## 個人開発の習慣

1. 作業前に `git status`。別の場所でも触ったなら `git pull`。
2. 作業の区切りで `git add .` と `git commit -m "何を変えたか"`。
3. 終えたら `git push`。
4. 大きく壊したら、まず `git log --oneline` で戻りたい版を探す。

これで、作る・変更履歴を残す・別PCへ持ち運ぶ・昔の版を確認する・安全に復元する、まで対応できます。
