00 / ウェブアプリとは何か

ウェブアプリ＝ブラウザーで、操作して使うアプリ。

ウェブアプリは、ブラウザー上で入力・選択・送信などをして、目的の作業を行う仕組みです。たとえば、予約する、投稿する、写真を共有する。情報を読むだけでなく、操作に応じた結果を受け取れることに注目してみましょう。

例：画像付きの掲示板
文章を入力して写真を選び、「投稿する」を押すと、投稿が保存されて画面に表示される。他の人もその投稿を見ることができます。

人形劇にたとえると、見える舞台と、それを支える舞台裏。

子どもたちがユーザーです。舞台を見たり「次はこの人形が見たい」とお願いしたりする場面を、ウェブアプリを使う場面に重ねてみます。

裏方の人 → プログラム
お願いを受けて、何をするか判断し実行する役割。掲示板なら、投稿内容の確認や保存の処理を担当します。
中央の一覧表 → データベース
人形の名前や出演順など、整理した情報を記録する場所のたとえ。掲示板なら、投稿文・投稿者・日時などを保存します。
左下の箱 → ストレージ
使う人形や小道具をしまう場所のたとえ。掲示板なら、アップロードされた写真などのファイルを保管します。

たとえとしての補足：一覧表の記録内容は、説明のために補った例です。また、実際にはデータベース自体もストレージ上に保存されます。「整理された情報」と「素材ファイル」の役割を分けて考えるためのたとえです。

お願いを送って、結果が画面に返ってくる。

掲示板でも、同じような流れになります。

  1. 1. 入力・送信ブラウザーで投稿文と写真を選び、サーバーへ送る。
  2. 2. 確認・保存プログラムが内容を確認し、DBやストレージに保存する。
  3. 3. 結果を返す保存した投稿の情報などを、ブラウザーへ返す。
  4. 4. 画面に表示フロントエンドが、投稿を画面に表示する。

「フロントエンド＝動きがない」ではありません。ブラウザー側でもJavaScriptで画面を動かせます。違いは、主にブラウザーで表示・操作を扱うか、サーバーで処理・データを扱うかです。計算ツールなど、ブラウザー内の処理だけで使えるアプリもあり、すべてにバックエンドやDBが必要なわけではありません。

では、このアプリを他の人にも使ってもらうには？

画面のファイルだけでなく、必要ならプログラムを動かす場所、データベース、ファイルの保管場所も用意し、つなぐ必要があります。この「必要な部品を、使える場所へ配置して動かす」話が、次のデプロイです。

01 / デプロイとは？

完成したものを、使える場所へ置く。

デプロイとは、パソコンの中だけで動く制作物を、URLから誰でも（または許可した人だけが）使える状態にすることです。画面だけ公開できても、必要な部品がなければアプリは動きません。

FRONTEND

フロントエンド

画面。HTML / CSS / JavaScript

BACKEND

バックエンド

API、認証、メール、権限制御

DATABASE

データベース

ユーザー、投稿、履歴、設定

STORAGE

ストレージ

画像、動画、PDF、添付

選ぶ基準：特に重要なのは「バックエンドで何を実行したいか」です。既存PHP、JavaScript/TypeScriptのAPI、常駐Node.jsでは向く場所が変わります。

02 / デプロイ先の候補

できることと、用意するものを比べよう。

デプロイ先は、作ったものをインターネット上で使えるようにする場所です。できることには重なりがあります。違いは「必要な部品がどこまで用意されているか」「何を自分で組み立て、管理するか」です。

まず、共通して目指せることを知ろう。
  • WebサイトやWebアプリを公開する
  • 画像・動画・PDFなどのファイルを保管する
  • データベースで情報を保存・検索する
  • 投稿や変更をリアルタイムに反映する
  • ログイン機能を作る

これは組み合わせや自分での準備も含めて実現できることです。すべてのサービスに5つが標準で付いているわけではありません。下の表では、別に用意するものや制限も示します。

画面側のHTML / CSS / JavaScriptと、サーバー側で動かすプログラムは別です。「使える言語・実行環境」の列では、主にサーバー側の違いを紹介します。

まずは、この3つの考え方を知ろう。

  • Cloudflare：必要な部品を選んで、自分で組み立てたい。
  • Firebase：ログインやデータ共有など、用意された部品をつないで作りたい。
  • VPS：使うソフトや動かし方を自由に決めたい。ただし、更新・安全対策・バックアップも自分で担当します。

これは優劣ではなく、作り方・管理の仕方の違いです。3つをすべて使う必要はありません。

まず見る3つの候補
サービス名特徴・別に必要なもの使える言語・実行環境料金プラン
Cloudflare必要な部品を選んで組み立てる。

Pagesは、HTML・CSS・JavaScriptなどの静的ファイルを置いて公開する場所。Workersは、入力内容の確認やデータの読み書きなど、サーバー側の動的な処理を受け持ちます。

ファイル保管にはR2、DBにはD1、リアルタイム通信にはWorkersとDurable Objectsなどを組み合わせます。

確認すること：ログインは認証ライブラリーや外部サービスなどで用意します。なお、Workersでも静的ファイルを公開でき、PagesにもWorkersの仕組みで動くFunctionsを追加できます。

画面はHTML / CSS / JavaScriptなど。サーバー処理は主にJavaScript / TypeScript。Workersという専用環境で実行します。Node.jsの機能は一部に対応し、既存コードがそのまま動くとは限りません。無料枠あり。Workers・DB・ファイル保管などで枠と課金が別です。使う量や機能に応じて有料になります。
Firebase用意されたアプリの部品をつなぐ。

Firebase Hostingは、HTML・CSS・JavaScriptなどを置いて画面を公開する場所。Cloud Firestoreは、投稿や予定などを整理して保存・検索できるデータベースです。

Realtime Databaseは、チャットやオンライン状態などの変更を、つながっている端末にすぐ共有できるデータベース。Cloud Firestoreもリアルタイム更新に対応します。ログインにはFirebase Authentication、写真や動画の保管にはCloud Storageを組み合わせます。

確認すること：DBは両方が必須ではなく、データの持ち方や検索の仕方で選びます。「誰が何を読める・書けるか」のルール設定は必要です。

画面はHTML / CSS / JavaScriptなど。サーバー処理のCloud FunctionsはNode.js（JavaScript / TypeScript）やPythonに対応します。無料のSparkと従量課金のBlaze。Cloud StorageやCloud FunctionsはBlazeへの登録が必要です。無料利用枠があっても、請求先の登録が必要な場合があります。
VPS自分で整える、自由度の高い作業場。

サイト公開・ファイル保管・DB・リアルタイム通信・ログインの仕組みを自分で設置できます。

確認すること：完成した機能セットではありません。ソフトの導入、更新、安全対策、バックアップも自分で担当します。

画面はHTML / CSS / JavaScriptなど。サーバー処理はNode.js、PHP、Pythonなど、OSに合う実行環境を自分で導入。使えるものは契約とサーバーの性能によります。一般に月額などの有料契約。性能・容量で料金が変わり、無料のお試し期間がある会社もあります。

ほかにも、こんな選択肢。

Vercelは画面の開発と公開、Renderはサーバープログラムの運用、Supabaseはデータベース中心の開発で検討できます。

WordPressや既存のPHPなら、レンタルサーバー（共用型）も身近な候補です。管理をできるだけ任せたいときは、VPSだけに絞らず検討しましょう。

Vercel画面づくりと、試して公開する流れをつなぐ。

サイト公開とサーバー処理をまとめやすく、ファイル保管にはVercel Blobも使えます。

確認すること：DB・ログインは外部サービスなどを接続。FunctionsはWebSocketサーバーになれないため、その方式のリアルタイム通信は別サービスを使います。

画面はHTML / CSS / JavaScriptなど。サーバー処理は主にJavaScript / TypeScript（Node.js）、Pythonなど。サーバー処理には実行時間などの制限があり、プログラムの常時起動用ではありません。無料のHobbyは個人・非商用向け。有料のProなどもあり、追加サービスや利用量で費用が変わります。
Render作ったサーバープログラムを動かす。

サイト公開に加え、WebSocketによるリアルタイム通信や、PostgreSQLのDBも利用できます。

確認すること：ログイン機能は自作・外部連携。画像などを長く保存するには、有料ディスクや外部ストレージなどが必要です。

画面はHTML / CSS / JavaScriptなど。サーバー処理はNode.js、Python、Ruby、Goなど。PHPなどはDocker（実行環境をまとめる仕組み）で動かせます。無料枠あり。ただし無料Webサービスは未使用時に休止し、無料DBにも期限があります。常時稼働や永続ディスクは有料プランで検討します。
Supabaseデータベースを中心にアプリを組む。

DB、ファイル保管、ログイン、リアルタイム配信をまとめて使えます。

確認すること：一般的なWebサイトの画面を公開する場所は、CloudflareやVercelなどに別途用意します。

画面側はJavaScriptなどから接続。DB操作はSQL、サーバー処理は主にTypeScript（Deno環境のEdge Functions）を使います。無料のFreeと有料のProなど。無料枠には容量・通信量の制限があり、利用が少ないプロジェクトは休止する場合があります。
レンタルサーバー（共用型）Web用に整えられた場所を借りる。

サイト公開とファイル保管ができ、DB付きプランならWordPressなども使えます。ログインはアプリ側で実装します。

確認すること：使える言語やDBは契約次第。常駐プログラムやWebSocketは制限されることが多く、その方式のリアルタイム通信は外部連携などを検討します。

画面はHTML / CSS / JavaScriptなど。サーバー処理は主にPHP。サーバーでNode.jsやPythonを動かせるかは会社・プランごとに確認します。一般に月額・年額の有料契約。容量やDBの有無でプランを選びます。VPSと同じく、会社ごとに条件が違います。

無料枠は「無制限」ではありません。容量だけでなく、通信量・処理回数・同時接続数などにも上限があります。有料プランの登録が必要でも、一定量まで無料の場合があります。VPSとレンタルサーバー（共用型）はサービスの種類の名前なので、契約する会社の条件を確認しましょう。

03 / 目的に応じたデプロイ先

やりたいことから、合いそうな場所を選ぶ。

まずは「何を作りたいか」を考えます。下の表は最初の候補です。実際には、料金・公開範囲・使う言語なども公式サイトで確認しましょう。

やりたいことまず考える部品最初に見る候補
作品紹介や学校紹介のページを公開したい画面を置く場所Cloudflare、Vercel、Firebase Hosting、レンタルサーバー（共用型）
WordPressや今あるPHPのページをそのまま使いたいPHPを動かせる場所レンタルサーバー（共用型）、VPS、Render
ログイン付きの掲示板や写真共有を作りたい画面 + ログイン + データ保存Firebase、Supabase。画面の公開先はCloudflareやVercelと組み合わせることもあります。
JavaScriptで作った画面と、小さなAPIを公開したい画面 + サーバー処理Cloudflare、Vercel
Node.jsやPythonのプログラムを、そのままの形でサーバーで動かし続けたい動き続けるサーバープログラムRender、VPS
リアルタイムチャット機能やリアルタイム性のあるアプリを作りたい画面 + 変更をすぐに届ける仕組みFirebase、Supabase。自分で通信処理を作るならCloudflare Workers + Durable Objects。
カレンダー、予定表などのデータ管理をしたい画面 + データ保存 + 利用者ごとのアクセス制限Firebase、Supabase。予定を複数人ですぐ共有するなら、リアルタイム機能も使います。
基幹システムのダッシュボードを作りたい画面 + 社内データとの連携 + 認証・権限管理社内システムへの接続条件に合う環境を選びます。VPSなどのサーバーやクラウド環境を検討し、画面の公開先は別に選ぶこともできます。

迷ったら、まず小さく公開してみよう。画面だけならCloudflareやVercel、データやログインが必要ならFirebaseやSupabase、既存PHPならレンタルサーバー（共用型）という順で考えると整理しやすくなります。

04 / ウェブアプリのデプロイのやり方

先に構成を決めてから、公開の手順へ。

  1. 用途を一文で書く。 例：「ログインした人が画像付きの投稿を残せる掲示板」。
  2. 必要な部品を選ぶ。 画面だけか、API・認証・DB・ストレージ・リアルタイムが必要かを確認します。
  3. 既存コードの条件を確認する。 PHPをそのまま使うか、JS/TSに作り直せるか、常駐Node.jsが必要かを分けます。
  4. 公開先を一つ決め、小さく試す。 画面を公開し、必要な部品を一つずつ接続します。
  5. 本番前に料金・権限・バックアップを確認する。 無料枠・請求先・公開範囲・環境変数を公式ページで確認します。
公開だけ → Cloudflare Pages 既存PHPフォームを変えたくない → 一般的なレンタルサーバー 新規フォームをJS / TSで作る → Cloudflare Workers 投稿やコメントをSQLで管理したい → Supabase 完成部品中心で早く作りたい → Firebase リアルタイムの部屋を柔軟に作りたい → Cloudflare Durable Objects 既存Node.js / Socket.IOを動かしたい → VPS または Render

05 / リアルタイム空間の考え方

動いている「今」と、残す記録を分ける。

現在座標や接続中ユーザーは、毎回DBへ保存せず、WebSocketやRealtimeで一時的に配信します。チャット履歴やプロフィールはDBに保存します。位置更新は毎秒2〜4回程度に間引き、ブラウザ側で補間します。

一時状態：接続中ユーザー、現在座標、方向 → Durable Objects / Realtime Database / Supabase Realtime 永続データ：ユーザー、部屋情報、チャット履歴、プロフィール → D1 / Firestore / PostgreSQL

二つの第一候補：部屋の状態を主役にするなら「Cloudflare Pages + Workers + Durable Objects + D1」。ログイン・プロフィール・検索などSQLデータを主役にするなら「Cloudflare Pages + Supabase」です。
